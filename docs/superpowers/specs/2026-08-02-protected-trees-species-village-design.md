# 臺北老樹、樹種介紹與里長資訊設計規格

日期：2026-08-02

## 1. 目標

在既有「臺北市行道樹透明化查詢平台」中加入三組互相關聯的能力：

1. 納入臺北市受保護樹木（臺北老樹／樹神），提供位置、官方樹齡、檔案照片、歷史故事與官方詳情頁。
2. 為平台實際收錄的每一種樹種產生可信、可追溯的介紹與臺北市統計資料。
3. 對修剪行程中的「里長建議」案件，顯示施作地點所屬里、現任里長、官方公開行動電話及里長簡介連結。

網站維持純靜態 GitHub Pages 架構。所有外部資料由 GitHub Actions 在部署前同步、驗證及壓縮，瀏覽器不直接依賴第三方 API。

## 2. 資料可信度原則

- 樹齡只採用臺北市受保護樹木官方資料的 `age` 或 `bornYear`；不得依胸徑、樹高或樹種自行推算。
- 官方樹齡屬調查或訪談估算時，介面標示「官方登錄樹齡／推估植栽年」，不得呈現為精密測年結果。
- 照片只連結官方檔案網址，不下載、重製或重新託管照片。
- 故事只使用官方 `historyInfo`、`envDescription` 等欄位，保留官方詳情頁作為完整來源。
- 行道樹或公園樹木若沒有官方樹齡、照片或故事，顯示「官方未提供」，不得用受保護樹木同樹種資料套用。
- 樹種介紹不得由模型或程式生成無來源的生態敘述。沒有官方文字介紹時，只顯示平台統計、官方學名／英文名及權威資料庫查詢連結。
- 里別與里長資料必須來自臺北市官方來源。模糊、跨里或無法驗證的地點顯示「里別待確認」，不得以字面相似度猜測。
- 電話只顯示臺北市鄰里服務網公開的現任里長公務聯絡資訊，並附來源與資料更新日期。

## 3. 官方資料來源

### 3.1 受保護樹木

- 臺北市資料大平臺「臺北市受保護樹木」CSV：作為完整樹籍清單、座標、地址、樹種、學名、英文名及管理單位的主要來源。
- 臺北市受保護樹木資訊平臺公開詳細資料 API：依樹木編號取得 `age`、`bornYear`、`images`、`historyInfo`、`envDescription`、`villageName`、管理單位及官方更新時間。
- 官方詳情頁固定使用 `https://eculture.gov.taipei/trees/zh-tw/tree/{樹木編號}`。

### 3.2 樹種資料

- 學名及英文名優先採用受保護樹木官方 CSV／API。
- 臺北市數量、行政區分布、常見路段／公園、平均胸徑與平均樹高，由平台收錄的行道樹、公園樹木及受保護樹木計算。
- 延伸閱讀連結使用臺灣植物資訊整合查詢系統（TAI2）、臺灣生物多樣性網絡（TBN）或臺北市政府植物介紹頁；只建立查詢連結，不複製不明授權全文。

### 3.3 里別與里長

- 里長姓名、公開行動電話、里長簡介 URL 與官方更新日期取自「臺北市鄰里服務網」。
- 修剪資料若已明載里名，直接以「行政區＋里名」比對官方里長名冊。
- 若只有地址或具座標地點，以臺北市官方區里界或門牌／地理資料進行空間判定。
- 若只有公園名稱，使用可稽核的「公園名稱 → 行政區 → 里」對照資料；對照紀錄必須保存來源 URL、查核日期與判定方式。
- 若一座公園跨越多個里，顯示全部可能里別並標示「跨里」，不指定單一里長。

### 3.4 富錦一號公園範例

使用者提供的官方里長簡介頁實際標示為「松山區東榮里」，並非「東隆里」。本平台以官方頁面為準：

- 地點：富錦一號公園
- 行政區：松山區
- 里別：東榮里
- 里長：鄭玉梅
- 公開行動電話：0933-902-948
- 里長簡介：`https://li.taipei/News_Content_VillageLeader.aspx?n=99B6C1D6A9596E73&sms=D982815F3A372FF5&s=04A7C7CC05945111`

此筆公園與里別的對應仍須由正式地理來源或公園地址／座標驗證；里長頁本身只能證明東榮里里長資訊，不能單獨證明公園位於該里。

## 4. 同步與快取架構

### 4.1 受保護樹木清單

每日資料工作流程下載官方 CSV，正規化後加入第三種樹木類型 `protected`。CSV 下載或驗證失敗時保留上一版可用資料，並讓工作流程失敗以發出警示。

### 4.2 詳細資料快取

官方詳細資料 API 不允許 GitHub Pages 直接跨來源讀取，因此由 GitHub Actions 建立精簡快取：

- 首次建置以低併發、限速及重試機制逐筆取得全部受保護樹木資料。
- 後續每日優先更新新樹、快取缺漏及失敗紀錄，再輪替更新最久未查詢的 300 筆；約兩週完成一輪。
- 從目前已部署的快取下載上一版作為增量起點；若無上一版才啟動完整建置。
- 每筆只保存展示必要欄位、第一張代表照片 URL、照片總數、故事文字及官方詳情 URL，不保存照片二進位檔。
- 單筆 API 失敗時保留該筆舊快取並記錄錯誤；不得用空值覆蓋既有有效資料。

### 4.3 里長資料

里長資料採週期性快照，至少每週重新驗證一次。任期更替或官方頁面改版時，由欄位驗證與差異報告阻止錯誤資料靜默發布。公開電話在 UI 中使用 `tel:` 連結，但原始資料仍保留官方格式。

## 5. 資料模型

### 5.1 樹木公開資料新增欄位

- `tree_type`: `street`、`park` 或 `protected`
- `protected_code`
- `village`
- `age_years`
- `born_year`
- `age_source`: 固定為 `official_protected_tree_registry` 或空值
- `scientific_name`
- `english_name`
- `management_unit`
- `photo_url`
- `photo_count`
- `story`
- `environment_description`
- `official_detail_url`
- `official_modified_at`
- `detail_fetched_at`

### 5.2 樹種介紹資料

- `species`
- `scientific_name`
- `english_name`
- `tree_count`
- `district_counts`
- `common_locations`
- `average_diameter_cm`
- `average_height_m`
- `protected_tree_count`
- `authoritative_links`
- `stats_updated_at`

若同一中文名對應不同學名，保留多筆候選與來源，不任意合併；若資料來源間學名衝突，UI 顯示「官方資料存在異名」，並列出來源。

### 5.3 修剪案件新增欄位

- `village`
- `village_match_method`: `source`、`address`、`coordinate`、`park_crosswalk`、`manual_verified` 或 `unresolved`
- `village_match_source_url`
- `village_verified_at`
- `village_leader_name`
- `village_leader_mobile`
- `village_leader_profile_url`
- `village_leader_source_updated_at`

只有 `requester_type = village_leader` 時顯示里長聯絡卡；承商查報與議員案件沿用既有的承商／議員欄位，不混入里長資訊。

## 6. 使用者介面

### 6.1 搜尋與結果卡片

- 搜尋篩選新增「受保護樹木／臺北老樹」類型。
- 受保護樹木使用「老樹／樹神」標章，卡片顯示樹木編號、行政區、里別、位置、樹種、胸徑、樹高、官方樹齡及更新日期。
- 點選卡片展開詳情：Google Maps、代表照片、故事摘要、管理單位、官方完整檔案與照片連結。
- 無樹齡、照片或故事時顯示「官方未提供」；快取尚未同步完成時顯示「詳細資料同步中」，不得誤標成官方沒有資料。

### 6.2 樹種介紹

- 點選任何樹種名稱開啟樹種介紹面板。
- 顯示臺北市實際統計、行政區分布、常見地點、平均胸徑／樹高、受保護樹木數量、學名、英文名及權威外部連結。
- 手機版使用單欄卡片；桌面版可使用摘要表格與行政區分布圖。

### 6.3 修剪行程與里長聯絡卡

「里長建議」案件顯示：

- 所屬行政區與里別
- 現任里長姓名
- 「撥打公開電話」按鈕
- 「查看里長簡介」官方連結
- 里別判定方式、來源及最後查核日期

若里別待確認、跨里或官方里長資料暫時缺漏，清楚顯示狀態，不提供猜測的姓名或電話。

## 7. 狀態透明化與錯誤處理

資料狀態區新增：

- 受保護樹木總筆數與最後更新時間
- 詳細資料快取涵蓋率、過期筆數與失敗筆數
- 有官方樹齡、照片及故事的筆數
- 樹種介紹數量與統計更新時間
- 里長資料最後同步時間
- 修剪地點已判定、跨里及待確認數量

任何必要資料源失敗時不發布空資料。選用資料源失敗時可發布，但必須在狀態區標示「沿用上一版」或「部分資料暫缺」。

## 8. 安全、隱私與效能

- 所有外部文字以文字節點呈現或先轉義，URL 僅允許 `https:`；電話連結只允許數字及 `+`、`-`。
- 不公開里長頁面未要求呈現的個人資訊，也不顯示里幹事手機、電子郵件等額外欄位。
- 故事及圖片採延遲載入；樹種統計另存精簡 JSON，避免增加主樹木清單首次載入量。
- 詳細快取腳本設逾時、重試上限、低併發與請求間隔，避免對官方服務造成過度負載。

## 9. 測試與驗收

### 自動測試

- 受保護樹木 CSV 欄位正規化、座標、樹木編號及詳情 URL。
- 詳細 API 的樹齡、植栽年、第一張照片、照片數量、故事及缺值處理。
- 舊快取保留、增量排序、輪替更新、失敗重試與防空資料發布。
- 樹種聚合統計及學名衝突處理。
- 里別直接比對、座標比對、公園對照、跨里與 unresolved 狀態。
- 里長頁欄位解析、電話清理與非里長案件不顯示聯絡卡。
- HTML 轉義、URL 白名單及手機版必要欄位。

### 驗收案例

1. 受保護樹木編號 668 可顯示官方樹齡、植栽年、照片數量、代表照片、位置、故事及官方詳情頁。
2. 沒有官方樹齡的行道樹顯示「官方未提供」，不出現推估數字。
3. 點選「榕」可看見平台統計、學名、英文名與權威資料庫連結。
4. 富錦一號公園的正式地理來源驗證為東榮里後，「里長建議」案件顯示鄭玉梅、0933-902-948及官方簡介連結。
5. 若正式地理來源不支持東榮里對應，該案件標示「里別待確認」，不得僅因使用者範例強制寫入。
6. 手機畫面中受保護樹木、樹種介紹及里長聯絡卡皆不產生水平捲動。
7. 官方詳細 API 或里長網站暫時失敗時，網站仍保留上一版有效資料並顯示資料狀態。

## 10. 不在本次範圍

- 推算一般行道樹或公園樹木的樹齡。
- 下載、重新壓縮或重新託管官方照片。
- 建立里長聯絡表單、代替使用者傳送訊息或蒐集陳情個資。
- 以第三方地圖文字搜尋結果作為唯一里界證據。
- 對修剪案件中的議員、承商或里長做績效評分。
