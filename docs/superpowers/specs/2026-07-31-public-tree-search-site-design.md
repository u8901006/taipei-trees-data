# 臺北行道樹透明化查詢網站設計

## 目標與受眾

網站服務一般市民，以手機優先的方式查詢臺北市真實行道樹資料。使用者可依行政區、路段與樹種篩選，查看行政區、路段、樹種、胸徑、樹高與更新日期。網站同時解釋資料來源、更新方式與推論限制，避免把資料缺漏誤讀為已確認的樹木移除。

## 資訊架構

單頁網站依序包含：

1. Hero：一句清楚的公共價值主張、資料筆數、行政區數與最新更新日期。
2. 搜尋工作區：行政區下拉選單、路段文字欄位、樹種文字欄位與重設按鈕。
3. 查詢結果：桌面使用緊湊表格，手機轉為可掃讀卡片；每頁 30 筆並提供分頁。
4. 透明化說明：資料來源、Git 稽核軌跡、更新頻率與使用限制。
5. 頁尾：李政洋身心診所首頁、訂閱電子報、Buy Me a Coffee 三個外部連結。

## 視覺設計

採深松綠、暖米白、苔綠與金棕色，搭配大字級中文標題、柔和圓角、清楚邊界與充足留白。背景使用 CSS 漸層及幾何色塊，不使用裝飾性 SVG。互動元件具明顯 focus 狀態；色彩對比、觸控尺寸與減少動態偏好皆納入設計。

## 資料與搜尋架構

`scripts/build_site_data.py` 從 `processed/trees.parquet` 讀取 canonical 13 欄，只輸出市民查詢所需欄位，依行政區建立 minified JSON，並產生 `manifest.json`。檔名採穩定雜湊，避免中文路徑與 traversal 問題。相同輸入必須產生 byte-stable 結果。

瀏覽器先載入 manifest。指定行政區時只下載該分區；未指定行政區時按 manifest 順序載入全部分區。搜尋採 Unicode NFKC、去除前後空白與大小寫正規化，再對路段與樹種做包含比對。結果以 30 筆分頁，並清楚顯示命中總數與目前範圍。

## 部署

`.github/workflows/pages.yml` 在 `main` 更新、每日排程或手動觸發時：安裝 Python、擷取官方 Open Data、正規化、建立搜尋索引、組裝靜態成品，並用 GitHub 官方 Pages actions 部署。首次發布會將同一份已驗證成品推至 `gh-pages` 並啟用 GitHub Pages，讓網站不必等待 PR 合併即可上線。

## 錯誤處理與安全

- manifest 或分區載入失敗時顯示固定、無敏感資訊的友善訊息。
- 搜尋文字只透過 `textContent` 顯示，不使用 `innerHTML` 注入資料。
- 外部連結使用 HTTPS；Buy Me a Coffee 的使用者提供網址會正規化為 HTTPS。
- 只發布查詢必要欄位，不暴露 secrets、原始模型回應或本機路徑。
- 資料更新日期與免責說明始終可見。

## 驗證標準

- Python 測試證明資料分區、欄位白名單、穩定輸出與空資料行為。
- Node 內建測試證明查詢正規化、篩選、分頁與安全顯示資料模型。
- HTML 契約測試證明語意標籤、搜尋欄位、結果容器、三個頁尾連結與無障礙標籤存在。
- Pages workflow 契約測試證明權限、觸發條件、資料建置與官方部署 actions 完整。
- 最終以實際 GitHub Pages URL 驗證 HTTP 200、主要標題、資料 manifest 與三個頁尾連結。
